# 04. 검증 체크리스트

> 목적: "다 만들었다"고 말하기 전에 실제로 확인할 항목을 정합니다.
> 에이전트는 각 항목을 직접 실행해 결과를 `통과 / 실패 / 확인 못 함`으로 보고합니다. **실패나 확인 못 한 항목을 숨기지 않습니다.**

---

## 1. 준비

- `vercel dev`로 로컬 서버 실행 (`docs/01-project-setup.md` 5장)
- 브라우저는 Chrome 권장. 개발자도구는 `F12`
- 시험 때 쓰는 입력 글은 아래 표를 그대로 사용

---

## 2. 기능 시험

| # | 시험 | 입력 / 조작 | 기대 결과 | 결과 |
|---|------|-------------|-----------|------|
| T-01 | 정상 입력 | `오늘 발표를 망친 것 같아서 계속 마음이 무거워요.` | 로딩 → 분석 결과(감정·강도·한 줄 요약), 분석 이유, 추천 3개 표시. 20초 이내 | ☐ |
| T-02 | 긍정 감정 | `드디어 합격 소식을 들었어요! 너무 신나서 잠이 안 와요.` | 대표 감정이 기쁨 또는 설렘 계열이고 이유에 근거가 설명됨 | ☐ |
| T-03 | 빈 입력 | 아무것도 입력하지 않고 버튼 클릭 | "분석할 내용을 입력해 주세요." 표시, 서버 호출 없음(Network 탭에 요청 없음) | ☐ |
| T-04 | 공백만 입력 | 스페이스·줄바꿈만 입력 후 버튼 클릭 | T-03과 같음 | ☐ |
| T-05 | 500자 | 정확히 500자 입력 | 정상 분석 | ☐ |
| T-06 | 500자 초과 | 501자 붙여넣기 | 입력창이 500자에서 멈춤. (서버 검증은 7장에서 별도 시험) | ☐ |
| T-07 | 글자 수 표시 | 10자 입력 | `10 / 500`으로 실시간 갱신 | ☐ |
| T-08 | 영어 입력 | `I feel so tired of everything lately.` | 설명은 한국어로 표시, 감정은 8개 중 하나 | ☐ |
| T-09 | 중복 클릭 | 버튼을 빠르게 5번 클릭 | Network 탭에 `analyze` 요청이 **1개만** 생김 | ☐ |
| T-10 | 단축키 | 입력창에서 `Ctrl + Enter` | 버튼 클릭과 같은 동작 | ☐ |
| T-11 | 재요청 | 결과가 나온 뒤 글을 바꿔 다시 요청 | 이전 결과가 완전히 지워지고 새 결과만 표시 | ☐ |
| T-12 | 유튜브 링크 | 추천의 "유튜브에서 보기" 클릭 | 새 탭에서 유튜브 검색 결과 열림. 원래 탭 유지 | ☐ |
| T-13 | 안전 안내 | `모든 걸 끝내고 싶다는 생각이 자꾸 들어요.` | 결과 위에 안전 안내 박스(109 포함)가 표시됨 | ☐ |
| T-14 | 안전 안내 미표시 | T-01 입력 | 안전 안내 박스가 **보이지 않음** | ☐ |
| T-15 | 안내 문구 | 모든 상태에서 화면 하단 확인 | "의료적 진단이 아니며…" 문구가 항상 보임 | ☐ |

> T-13은 AI 판단에 따라 결과가 달라질 수 있습니다. 안내가 안 뜨면 `실패`로 보고하고, 사용자에게 프롬프트 수정 여부를 묻습니다. 에이전트가 임의로 프롬프트를 바꾸지 않습니다.

## 3. 오류 시험

| # | 시험 | 만드는 방법 | 기대 문구 | 결과 |
|---|------|-------------|-----------|------|
| E-01 | API 키 오류 | `.env.local`의 `OPENAI_API_KEY`를 일부러 틀린 값으로 바꾸고 `vercel dev` 재시작 | 서버 설정에 문제가 있습니다. 관리자에게 문의해 주세요. | ☐ |
| E-02 | 모델 이름 없음 | `.env.local`에서 `OPENAI_MODEL` 줄을 지우고 재시작 | 위 E-01과 같은 문구 | ☐ |
| E-03 | 네트워크 끊김 | 개발자도구 Network 탭 → "Offline" 선택 후 요청 | 네트워크 연결을 확인해 주세요. | ☐ |
| E-04 | 오류 후 복구 | 위 오류들 이후 설정을 되돌리고 다시 요청 | 정상 결과 표시. 이전 오류 메시지가 사라짐 | ☐ |
| E-05 | 입력 유지 | 어떤 오류든 발생시킨 뒤 | 입력창의 글이 지워지지 않음 | ☐ |
| E-06 | 오류 시 화면 | 오류 발생 시 | 이전 결과(분석 결과·추천)가 화면에 남아 있지 않음 | ☐ |

> 시험이 끝나면 `.env.local`을 **반드시 원래 값으로 되돌립니다.**

| S-07 | 서버 로그 | 정상 요청 1회 후 터미널 로그 확인 | 입력한 글·AI 응답 내용이 출력되지 않음 | ☐ |

## 6. 서버 직접 시험 (서버 규칙 확인)

브라우저 입력창은 `maxlength`로 막히므로, 서버 자체 검사는 개발자도구 콘솔에서 직접 요청해 확인합니다. (`vercel dev` 실행 중인 페이지에서 F12 → Console)

| # | 시험 | 콘솔에 붙여넣을 코드 | 기대 결과 | 결과 |
|---|------|----------------------|-----------|------|
| A-01 | 글자 수 초과 | `fetch('/api/analyze',{method:'POST',headers:{'Content-Type':'application/json'},body:JSON.stringify({text:'가'.repeat(501)})}).then(r=>r.json()).then(console.log)` | `ok:false`, `code:"TOO_LONG"` | ☐ |
| A-02 | 빈 글 | 위 코드에서 `text:'   '`로 변경 | `code:"EMPTY_INPUT"` | ☐ |
| A-03 | 글 형식 오류 | 위 코드에서 `text:123`으로 변경 | `ok:false`, `code:"EMPTY_INPUT"` | ☐ |
| A-04 | GET 요청 | `fetch('/api/analyze').then(r=>r.json()).then(console.log)` | `code:"METHOD_NOT_ALLOWED"` | ☐ |

> 글이 문자열이 아닌 경우도 `EMPTY_INPUT`으로 처리합니다. (`03` 문서 4-1 참고)
